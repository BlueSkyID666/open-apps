## What the AGPL-3.0 lets you do

The GNU Affero General Public License version 3 is the strongest common copyleft licence. You may use, study, modify and self-host the software for any purpose, including inside a business. For self-hosting an app unchanged — the way most people use the apps listed here — it asks nothing more than keeping its notices.

## The network clause

AGPL-3.0 is [GPL-3.0](/licenses/gpl-3.0/) with one addition. If you **modify** the program and let users interact with it **over a network** — a web app, an API, a hosted service — you must offer those users the complete source code of your modified version under AGPL-3.0.

So:

- self-hosting an unmodified AGPL app for your team: no source to publish;
- changing the code and running it as a service for others: publish your changes to those users;
- distributing copies: the same obligations as GPL-3.0.

## Can I use AGPL-3.0 code in a commercial product?

You can run it commercially. You cannot build a closed-source product or service on modified AGPL code without sharing that code with its users. Many AGPL projects are open-core and sell a commercial licence or enterprise edition for exactly this case; their pages here say so.

## AGPL-3.0 compared with other common licences

| | [MIT](/licenses/mit/) | [Apache-2.0](/licenses/apache-2.0/) | [GPL-3.0](/licenses/gpl-3.0/) | AGPL-3.0 |
|---|---|---|---|---|
| Self-host unchanged | Yes | Yes | Yes | Yes |
| Modify and offer as a service without sharing | Yes | Yes | Yes | No |
| Distribute inside a closed-source product | Yes | Yes | No | No |
| Explicit patent grant | No | Yes | Yes | Yes |

## Things to check in the apps listed here

AGPL is common among self-hosted apps with a company behind them: the core is AGPL, while an `ee` or enterprise directory, a cloud service or signed builds are sold separately. Some also ask contributors to sign a contributor licence agreement. Each app's page on Open App Scout notes these under "Licence in practice".
